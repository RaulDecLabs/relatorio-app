2. Estrutura do Banco de Dados Criada

O banco de dados foi estruturado com as tabelas fundamentais de DW (Data Warehouse) e segurança:

  1. clients: Registra seus clientes. Adicionei a coluna share_token (UUID) que serve como o link secreto do cliente.
  2. metrics_daily: Armazena os dados consolidados dia a dia de cada canal (gasto, impressões, cliques, conversões, receita).
  3. metrics_raw: Histórico do payload bruto recebido para auditoria.
  4. ingest_logs: Histórico de execuções e status das integrações de dados.

Acesso Público Seguro via Funções RPC:

Para permitir que os clientes vejam seus relatórios de forma pública e segura (sem expor o restante do banco), criei duas funções seguras (SECURITY DEFINER) que filtram os dados automaticamente pelo token do cliente:

  • get_shared_client_details(p_share_token): Retorna o nome, logo e cores do cliente.
  • get_shared_metrics(p_share_token): Retorna apenas as métricas de anúncios e conversões daquele token específico.

3. Passo a Passo do n8n (Integração Google e Meta)

O n8n será responsável por extrair dados diariamente das APIs de anúncios e injetar no banco de dados.

Fluxo de Trabalho no n8n:

  1. Trigger Cron: Configurado para rodar diariamente (ex: às 01:00 AM).
  2. Nó Google Ads: Busca o custo (spend), cliques e conversões filtrados pela data de ontem.
  3. Nó Meta Ads (Facebook): Busca o custo, cliques e compras (compras no site/leads).
  4. Nó Google Analytics 4: Busca o total de cliques externos e eventos de rolagem (scroll) do site.
  5. Nó Code (Formatação): Formata os dados de cada plataforma no formato JSON padrão esperado pela nossa API.
  6. Nó HTTP Request (Envio): Faz um POST enviando os dados para o seu app local ou em produção.

Importante: Assinatura de Segurança HMAC

A API do InsightOS exige que as requisições do n8n venham assinadas no cabeçalho x-ingest-signature usando a chave secreta HMAC definida em seu ambiente. Isso garante que nenhum invasor consiga enviar dados falsos ao seu banco.

Estrutura de JSON Esperada pela API:

{
  "client_id": "ID_DO_CLIENTE_NO_BANCO",
  "source": "google_ads", // ou 'meta_ads', 'google_analytics'
  "rows": [
    {
      "metric_date": "2026-06-11",
      "scope": "account",
      "entity_id": "id-da-conta-ou-campanha",
      "entity_name": "Nome da Conta/Campanha",
      "dimensions": {},
      "metrics": {
        "clicks": 150,
        "spend": 45.20,
        "conversions": 12
      }
    }
  ]
}

4. Rastreamento de Cliques e Rolagem (Scroll) no Site

A melhor forma de medir cliques e rolagem de página sem precisar mexer em códigos JavaScript complexos é usando o Google Analytics 4 (GA4).

Ele rastreia por padrão:

  • scroll: Sempre que o usuário chega a 90% da altura da página.
  • click: Cliques em links externos.

Para ativar, vá no painel do GA4 do cliente em Administrador > Fluxo de Dados > Configurações do Fluxo e ative a Medição Otimizada.

5. O Link de Compartilhamento no Frontend

Seus links de cliente terão este formato: http://localhost:8080/shared/[SHARE_TOKEN]

No frontend, construiremos uma tela limpa, sem a barra lateral de administração, que carrega as cores e logotipo personalizados do cliente e renderiza os gráficos de evolução de cliques, conversões e ROAS comparativo.
